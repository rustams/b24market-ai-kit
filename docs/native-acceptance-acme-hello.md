# Нативная приёмка acme.hello на чистом тестовом Bitrix24

Дата подготовки: 15.10.2026. **Это инструкция будущих действий, а не отчёт об их выполнении.** Подключений, установки, запросов к БД портала и изменения прав не было. Выполняет администратор после отдельного разрешения владельца лицензированного disposable стенда.

## 1. Выберите проверяемый канал и пакеты

Модуль PHP/D7, namespace `Acme\Hello`, компонент `acme:hello.demo`; в проверенных пакетах включено опциональное MySQL-хранилище `b_acme_hello_note`. Минимумы установщика: PHP 8.2.0 и main 23.0.0. Реальную совместимость надо подтвердить, не выводить из этих чисел.

| Пакет | Назначение | SHA256 |
|---|---|---|
| [Полная 0.2.1](security-audits/acme.hello/last_version.zip) | Чистая установка / повторная поставка кода 0.2.1 | `305063f2591bc9f64d634bfeab476e2161d238b82ae7f5321863d5cbe077ba96` |
| [Delta 0.2.1](security-audits/acme.hello/0.2.1.zip) | Только обновление точной базовой 0.2.0 | `2fdd38b14c580bce5f792a40df7a8b62bc2f8fd888af3c78691cc90b74b6b729` |
| Полная базовая 0.2.0 | Начало отдельного прогона обновления | `4f489f79912fe091b04a16b5e2ad5998bdfa469f0cc34e46b0b7144f469daa3e` |

Точная база delta — generated commit `141af1d6a6501979d9d89a37143fa5cb9d3077a5`, результат — `c32dcf3cdba3c906dc02a780a48d0d543c4ab359`. Эти Git-объекты принадлежат локальному демонстрационному проекту, не истории основного репозитория starter-kit. Пересоздание произвольной «0.2.0» новым генератором не даёт нужную базу.

Базовая полная 0.2.0 сохранена локально в `.verification/security-flow/before-build/last_version.zip` исходного workspace; в Git её нет. Перед прогоном B запросите у ответственного этот точный файл и проверьте SHA. Если он отсутствует, прогон B заблокирован: подготовьте другую явно зафиксированную пару full/base + delta, затем заново проверьте её. Базовая версия предшествует security-исправлениям; использовать только изолированно, без реальных данных, при display_errors=Off и запрете внешнего доступа.

Полная сборка внутри имеет `.last_version/`; delta — `0.2.1/`. Не устанавливайте delta на чистый портал и не пытайтесь обновить уже установленную 0.2.1 этим же переходом.

Для **нативной Marketplace-приёмки** партнёр должен подтвердить право на prefix `acme`, доступность решения `acme.hello` в тестовом канале и допустимый тестовый лицензионный ключ. Это демонстрационный ID; его доступность в кабинете не подтверждена. Загрузка пакетов в кабинет — отдельное согласованное действие, не публичная публикация. Если данный ID недоступен, перенесите сценарий на согласованный vendor ID, пересоберите оба пакета и повторите security flow; прежние SHA к новому ID не относятся.

Без партнёрского канала можно отдельно проверить native D7 installer на лицензированном стенде через ручную поставку собственного модуля в `/local/modules/acme.hello`, но это **не закрывает Marketplace-доставку и обновление**. Не запускайте updater вручную вместо SiteUpdate, не перемещайте установленный модуль и не делайте симлинков.

## 2. Подготовьте стенд и исходную точку

1. Запишите адрес стенда, редакцию/лицензию, PHP веб-сервера и CLI, версию main, MySQL, число app-узлов и FPM/OPcache policy. Для первого прогона предпочтителен один узел; это не проверка кластера.
2. Ответственный подтверждает: стенд disposable, доступ извне ограничен, реальных данных нет, разрешены установка/фикстуры/удаление собственных объектов. Выберите двух обычных тестовых пользователей из реальных метаданных стенда; ID заранее не выдумывать.
3. Проверьте приватный PHP error_log вне DOCUMENT_ROOT, display_errors=Off, права и ротацию. Администратор Bitrix не заменяет OS-права web-user. Не используйте chmod 777 и не меняйте общий Composer/vendor.
4. Сделайте полный snapshot чистого стенда S0, проверьте способ восстановления и хранение вне web root. Секреты и лицензионные файлы не помещать в Git/отчёт.
5. Проверьте, что acme.hello не зарегистрирован; собственной таблицы, четырёх опций, активного компонента и обеих копий каталога модуля нет. Любой остаток означает, что стенд не чистый: выяснить владельца или восстановить S0, не удалять наугад.
6. Сохраните исходные хеши соседних компонентов и ACL/меню тестового раздела, список собственных handlers/agents — ожидается 0. Не считывайте содержимое бизнес-таблиц других модулей.
7. На рабочей машине проверьте SHA архивов, их состав по full.manifest.json/update.manifest.json и привязку security-journal к full 0.2.1. Проверки ZIP уже выполнены локально; перед доставкой сверить полученные байты ещё раз.

Read-only SQL для администратора после разрешения; строки NAME относятся только к данным этого модуля:
```sql
SELECT ID FROM b_module WHERE ID = 'acme.hello';
SHOW TABLES LIKE 'b_acme_hello_note';
SELECT NAME, VALUE FROM b_option
WHERE MODULE_ID = 'acme.hello'
  AND NAME IN ('greeting', 'schema_version', 'storage_cursor', 'files_manifest');
```
Не запускайте SELECT из note-таблицы до проверки её существования. Для сравнения состояния фиксируйте только synthetic данные и собственные опции.

## 3. Прогон A: чистая установка актуальной 0.2.1

1. Из S0 получите полную 0.2.1 через согласованный **тестовый** партнёрский канал. Не распаковывайте `.last_version` вручную в ядро. Если выбран отдельный ручной D7-прогон, администратор доставляет содержимое `.last_version` только в свой `/local/modules/acme.hello`; такой прогон помечается отдельным каналом.
2. Откройте штатный список модулей/установленных решений и установите «Приветствие» (`acme.hello`) через административную форму. Названия разделов зависят от версии; ориентируйтесь на ID решения. Не вызывайте DoInstall из CLI.
3. Если штатная форма приводит к отказу POST/CSRF, остановитесь и сохраните запрос/метод и безопасную ошибку. Не отключайте проверки ради зелёной установки.
4. Проверьте регистрацию, версию 0.2.1, PARTNER_NAME=Acme, PARTNER_URI=https://example.org, наличие таблицы и отсутствие строк в ней. Через реальный Loader подтвердите доступность `Acme\Hello\Demo` и `NoteTable`.
5. Фактический путь получите через `Loader::getLocal('modules/acme.hello/install/version.php')` в приватной административной диагностике. Запишите его; убедитесь, что нет второй копии в local/bitrix. Штатное размещение не менять вручную.
6. Проверьте активные файлы `/local/components/acme/hello.demo`: их хеши совпадают с одноимёнными файлами install/components внутри установленного пакета. `files_manifest` содержит эти хеши; `schema_version=1`, `storage_cursor=0`, greeting имеет начальное значение.
7. Проверьте: общие страницы, меню и ACL не изменены; handlers/agents модуля отсутствуют. Пустые контейнеры каталогов сами по себе не считаются лишними компонентами.

**Ожидается:** установка завершена без ошибок, собственные объекты созданы один раз, соседние объекты неизменны. При ошибке проверить регистрацию, файлы, опции и таблицу — отсутствие сообщения не доказывает rollback.

## 4. Использование и контрольные данные

1. В настройках модуля сохраните `UAT acme.hello — сохранить после обновления`. Откройте настройки повторно, убедитесь в сохранении.
2. Администратор создаёт отдельную тестовую страницу средствами Bitrix и размещает `acme:hello.demo`. Страницу создаёт человек для приёмки, не установщик; её сохранение после удаления ожидаемо. Не переиспользовать чужую страницу.
3. Откройте страницу с обычным пользователем R и пользователем D; отдельно проверьте анонимный доступ. Права назначаются только тестовым группам/модулю, без расширения CRM. Учтите также ACL самой страницы: для проверки module denial страница должна разрешать вход соответствующей тестовой группе.
4. В `?filter=` интерфейс должен показывать «Приветствие»; `?filter=status` — состояние; неизвестный filter должен отвергаться без внутренних исключений. Сохраните `<script>alert(1)</script>` как synthetic greeting: в компоненте он отображается текстом. Затем верните контрольное приветствие.
5. Для проверки сохранения **строк таблицы**, а не только опций, администратор один раз добавляет две synthetic заметки для двух выбранных пользователей через приватный CLI runner вне web root, подключив реальный prolog и Loader. Вызов ORM: `Acme\Hello\NoteTable::add(['OWNER_ID' => $actualUserId, 'TEXT' => 'UAT-A-20261015'])`; второй маркер `UAT-B-20261015`. Проверить Result::isSuccess и сохранить возвращённые ID. Это отдельно согласованная запись только в собственной test-таблице, не публичный endpoint. UI добавления заметок в примере нет.
6. Реальными сессиями пользователей проверьте `NoteTable::readOwn`: своя запись доступна, чужая возвращает null. Для этого нужен временный защищённый test harness, возвращающий лишь факт доступа, без раскрытия чужого TEXT; не создавайте незащищённую debug-страницу. Без такого harness пункт остаётся открытым; CLI с подменённым USER не заменяет пользовательский тест.
7. Сохраните точные собственные строки `ID, OWNER_ID, TEXT`, greeting, schema_version, storage_cursor и file hashes. Прочие параметры ядра/пользователей в отчёт не переносить. Сделайте snapshot A1.

Опциональные E/W/X и CSV проверяются защищённым harness: export требует E, POST/CSRF; настройки X, просмотр R. Кнопки экспорта и UI редактирования заметок в базовом примере нет. Если harness не подготовлен, не отмечайте эти операции принятыми по отсутствующей кнопке.

## 5. Прогон B: штатное обновление 0.2.0 → 0.2.1

Этот прогон начинается **с восстановленного S0**, а не с установленной в прогоне A версии 0.2.1. Если A ещё нужен, сохраните его snapshot.

1. Проверьте точную полную базовую 0.2.0 по SHA из раздела 1, получите/установите её штатно через тестовый канал. Подтвердите версию и исходные хеши, единственную копию модуля.
2. Выполните раздел 4: greeting и две synthetic строки. Запишите их фактические ID и все собственные technical options. Сделайте B0 backup БД и согласованного комплекта module+active component.
3. Предложите в тестовом канале именно delta 0.2.1 от указанной базы. Перед обновлением проверьте, что установленная версия — 0.2.0 и её файловый состав соответствует базе. Одна строка версии недостаточна.
4. Запустите штатное обновление из административного интерфейса. Не повторять DoInstall, не переустанавливать и не копировать delta поверх вручную.
5. После завершения проверьте версию 0.2.1 и файлы по full.manifest.json; служебные updater/description, доставленные обновлением, дополнительно проверяются по update.manifest.json. Не требуйте полного совпадения наборов full и delta: служебные файлы отличаются по назначению.
6. Проверьте hashes активных component files и files_manifest; greeting и обе строки должны сохраниться **побайтно**, ID/OWNER_ID также. schema_version=1, storage_cursor не сброшен при существующей таблице.
7. Повторите настройки, компонент, права, effective filter и безопасные ошибки; проверьте private logs. Примените согласованную FPM/OPcache policy и подтвердите фактически исполняемый код. CLI cache invalidation не доказывает обновление FPM.
8. Повторное применение той же версии проверяйте только если тестовый штатный клиент предоставляет документированный способ. Если его нет, оставьте native повтор открытым: прямой include updater не является эквивалентом.

**Ожидается:** штатное обновление без повторной установки, данные/настройки сохранены, исходник и активные копии согласованы. При сбое после updater клиент может частично заменить код; не обещается общая атомарность. Остановитесь и восстановите B0 как согласованный комплект кода/БД по решению ответственного.

## 6. Удаление с сохранением на версии 0.2.1

1. Перед удалением сохраните snapshot и контрольные строки/опции. Откройте штатное удаление acme.hello.
2. На собственной форме **не отмечайте** «Удалить все данные и настройки этого модуля». Нажмите «Удалить модуль» и завершите штатные шаги.
3. В новом запросе проверьте отсутствие регистрации; Loader::includeModule не должен успешно подключать удалённый модуль. Проверьте сохранность note-таблицы, обеих строк, greeting, schema_version, storage_cursor и files_manifest.
4. Известные активные файлы компонента должны быть удалены. Пустые каталоги допустимы. Чужие файлы не должны удаляться; код модуля может оставаться или удаляться штатным клиентом — его судьбу фиксируйте отдельно от данных/регистрации.
5. Собственная test-страница остаётся; она не должна возвращать прежние данные через уже открытый/кэшированный компонент после удаления. Страница может сообщать об отсутствии компонента/модуля — это ожидаемо. Перезагрузите её новым запросом.
6. Соседние файлы, меню/ACL и чужие настройки неизменны. В модуле нет handlers/agents; их число по-прежнему 0.

**Ожидается:** модуль выключен, пользовательские данные и настройки сохранены. Не очищать таблицы/options вручную перед следующей установкой.

## 7. Повторная установка с сохранёнными данными

1. Если штатный клиент удалил исходный код, получите полную 0.2.1 снова из согласованного канала. Если он остался, проверьте версию и хеши, а не накладывайте вторую копию.
2. Установите штатно. Проверьте регистрацию и активные hashes, schema_version=1, сохранённые greeting и обе строки с теми же ID/OWNER_ID/TEXT. storage_cursor должен остаться прежним при существующей таблице.
3. Повторите browser сценарий, module rights и owner isolation. Не назначайте всем X для упрощения проверки.
4. Отдельный regression на сохранённое приветствие `__KIT_ABSENT__`: сохраните его через настройки, выполните keep-data uninstall/reinstall и убедитесь, что именно этот текст сохранился. После проверки верните обычный UAT marker.

## 8. Дополнительный regression: таблица удалена, опции остались

Только на отдельной disposable ветке snapshot; это намеренное уничтожение test-таблицы, которое требует явного разрешения. Не смешивать с обычным сохранением данных.

1. Из рабочего 0.2.1 выполните удаление **с сохранением**.
2. Администратор удаляет только `b_acme_hello_note` и задаёт собственную опцию `storage_cursor=999` через Option. Другие опции, включая greeting и files_manifest, не очищать. Запишите, что synthetic строки уничтожены намеренно; не требовать их восстановления.
3. Проверьте отсутствие таблицы и регистрации, наличие старых опций. Установите полную 0.2.1 штатно.
4. Ожидается новая пустая таблица, storage_cursor=0, сохранённый greeting и корректные active copies. Старое техническое состояние не должно мешать новой работе.
5. После этого прогона восстановите предыдущий snapshot, если требуется продолжить сценарий с сохранёнными строками.

## 9. Полное удаление

1. На disposable установленном 0.2.1 подготовьте backup, проверьте, что удаляются только synthetic данные этого модуля.
2. В форме удаления **явно отметьте** «Удалить все данные и настройки этого модуля», затем подтвердите штатное удаление.
3. Проверьте: нет регистрации, note-таблицы, собственных greeting/schema_version/storage_cursor/files_manifest; известные активные component files отсутствуют. Собственный каталог кэша очищен; пустые каталоги допустимы.
4. Системные параметры лицензирования партнёрского клиента, если они появились, рассматриваются отдельно; не удаляйте их произвольным SQL. Они не являются созданными нами четырьмя опциями. Зафиксируйте расхождение, а не требуйте стирания всего b_option.
5. Test-страница, ACL и тестовые пользователи/группы сохраняются: установщик ими не владеет. Их cleanup выполняет ответственный отдельно. Соседние таблицы, файлы, handlers и agents неизменны.
6. Для подтверждения действительно свежего состояния снова установите полную 0.2.1: ожидаются defaults greeting, пустая таблица, cursor=0 и без старых synthetic записей. Затем по согласованию восстановите S0.

Падение после MySQL DROP может быть необратимым без backup. Не делайте blind retry и не объявляйте rollback успешным только потому, что активные файлы вернулись.

## 10. Фиксация результатов и остановка при сбое

Для каждого этапа запишите: время, ответственного, фактические версии/узел, hash пакета, registration/table/row/option state до и после, hashes module/active copies, безопасный browser результат, ссылки на приватные server logs и snapshot. Не сохранять cookies, sessid, credentials, лицензионные ключи и чужие персональные данные.

| Этап | Ожидаемый результат | Факт / доказательство | Статус |
|---|---|---|---|
| A: clean 0.2.1 install | Собственные объекты, default state, Loader и UI | | Открыто |
| B: exact 0.2.0 → 0.2.1 | Штатный SiteUpdate, данные и options сохранены | | Открыто |
| Keep-data uninstall | Нет регистрации/active files, DB/options сохранены | | Открыто |
| Reinstall | Те же данные, cursor сохранён | | Открыто |
| Missing table + retained options | Новое пустое storage, cursor=0, greeting сохранён | | Открыто |
| Explicit purge | Собственные данные/options удалены, соседи сохранены | | Открыто |
| Fresh after purge | Нет прежних данных, начальные defaults | | Открыто |
| Roles/direct URL/CSRF/cache/owner | Права и конфиденциальность подтверждены на сервере | | Открыто |
| OS/logs/FPM/cluster | Реальная конфигурация проверена в заявленном объёме | | Открыто |

При ошибке остановиться на текущем этапе, сохранить безопасные доказательства и состояние. Не чинить ядро, не отключать CSRF, не менять права глобально, не запускать DoInstall при обновлении. Восстановление snapshot — отдельное решение владельца стенда. HTTP 200, зелёные mocks и security-journal не закрывают нативную приёмку.
